# INC-2026-0915: Elevated card latency during fraud API slowdown

## Summary
Card authorizations were slow and some were declined for 19 minutes while the fraud provider was degraded.

## Impact
- **Severity:** SEV3
- **Date:** 2026-09-15, 19:40 to 19:59 (Asia/Colombo), 19 minutes
- **Affected services:** Card Authorization Service (`card-auth-service`), Fraud Scoring Client (`fraud-scoring-client`)
- **Customer impact:** 1,450 transactions failed or timed out; about 1,200 customers affected.
- **Incident commander:** Dilani Fernando

## Detection
Latency alert at 19:42.

## Timeline
| Time | Event |
|---|---|
| 19:40 | VeriScore latency rises to 5 s. |
| 19:42 | Latency alert. |
| 19:50 | Circuit breaker not opening; timeout found set to 12 s instead of 800 ms. |
| 19:59 | Timeout corrected by configuration; breaker opens and fallback takes over. |

## Root Cause
The fallback existed but a configuration migration in August reset the fraud call timeout to a library default of 12 seconds. Slow responses never counted as failures, the circuit breaker stayed closed, and authorizations kept waiting on the external provider.

## Contributing Factors
- Configuration migration had no test for timeout values.
- No synthetic test that exercises the fallback path.

## Resolution
Timeout restored to 800 ms.
